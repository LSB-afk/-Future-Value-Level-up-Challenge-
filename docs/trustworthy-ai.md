- 작성일: 2026-09-16
- 자료 학습 기준일: 2026-09-15
- 대상: FitHome의 기획·개발·검증·운영 담당자
- 범위: TAILOR, EU ALTAI, TTA 일반 분야 안내서, EU AI Act, NIST AI RMF, CDAO Toolkit, AI Verify의 핵심 내용
- 문서 성격: 학습 요약과 적용 제안. 아래 요구사항·평가 지표는 구현 완료나 인증 취득을 뜻하지 않는다.

FitHome은 예산·통근·가구 조건에 맞는 주거 선택을 돕는 서비스다. 이 문서는 신뢰성 AI 원칙을 제품 요구사항, 테스트, 운영 기록으로 연결하기 위한 기준을 정리한다. 저장소의 기존 문서에는 MoveValue 명칭이 함께 사용된다.

## 1. 신뢰할 수 있는 AI의 의미

TAILOR가 설명하는 Trustworthy AI는 전 생애주기에 걸쳐 **합법성, 윤리성, 기술적·사회적 견고성**을 갖추는 것을 지향한다. 모델의 정확성, 데이터의 적절성, 사용자에게 미치는 영향, 조직의 책임과 운영 방식이 함께 고려된다.

여기서 좁은 의미의 신뢰성인 Reliability는 예상한 조건에서 시스템이 일관되게 동작하는 성질이다. Trustworthy AI는 안전성, 공정성, 개인정보 보호, 설명가능성, 인간의 감독 등을 포함하는 더 넓은 개념이다.

용어를 사용할 때는 다음을 구분한다.

| 개념 | 확인할 내용 |
| --- | --- |
| 투명성 | AI 사용 사실, 데이터 출처, 시스템의 목적·한계·역할을 알 수 있는가 |
| 설명가능성 | 개별 추천이나 결과의 근거를 이해할 수 있으며, 설명이 실제 계산·처리 과정에 부합하는가 |
| 견고성 | 입력 변화, 데이터 누락, 공격, 외부 API 장애 등에서도 적절하게 동작하는가 |
| 안전성 | 잘못된 결과와 시스템 중단으로 발생할 수 있는 피해를 식별하고 줄이는가 |
| 공정성 | 특정 집단에 발생하는 부당한 불이익을 맥락에 맞는 기준으로 평가·완화하는가 |
| 책임성 | 결정과 변경을 추적하고, 책임자·문제 신고·정정 절차를 확인할 수 있는가 |
| 인간의 감독 | 담당자가 필요한 정보와 권한을 갖고 결과를 검토·수정·중단할 수 있는가 |

설명의 유창함은 실제 판단 과정과의 일치를 입증하지 않는다. 공정성 지표도 사용 목적과 영향을 받는 집단에 따라 선택해야 한다. 가명처리와 익명처리 역시 구분하며, 가명처리만으로 재식별 위험이 사라진다고 가정하지 않는다.

근거: [TAILOR 개요](http://tailor.isti.cnr.it/handbookTAI/TAILOR.html), [투명성](http://tailor.isti.cnr.it/handbookTAI/Transparency/Transparency.html), [견고성과 안전성](http://tailor.isti.cnr.it/handbookTAI/Technical_Robustness_and_Safety/Technical_Robustness_and_Safety.html), [개인정보 보호](http://tailor.isti.cnr.it/handbookTAI/Privacy_and_Data_Governance/Privacy_and_Data_Governance.html).

## 2. 자료별 역할

| 자료 | 역할 | 프로젝트에 남길 산출물 예시 |
| --- | --- | --- |
| TAILOR Handbook | 기본 개념과 원칙의 의미·관계 이해 | 용어 정의, 원칙별 요구사항 |
| EU ALTAI | 윤리 원칙을 자기평가 질문으로 구체화 | 질문별 답변, 근거, 개선 조치 |
| TTA 개발 안내서 | 개발 생애주기별 실무 점검 | 적용 항목, 테스트, 데이터·모델 명세 |
| EU AI Act | 적용 범위와 위험 분류에 따른 법적 의무 이해 | 적용성 검토, 해당 의무와 증빙 목록 |
| NIST AI RMF | 조직·사용 맥락·측정·대응을 연결하는 위험관리 | 위험 목록, 담당자, 측정·대응 기록 |
| CDAO Toolkit | 책임 있는 AI를 프로젝트 운영에 적용 | 역할 분담, 우려사항, 완화·추적 기록 |
| AI Verify / Moonshot | 기술 시험과 절차 점검을 통한 증거 확보 | 평가 데이터셋, 테스트 결과, 개선 이력 |

원칙과 질문은 평가의 출발점이다. 적합한 요구사항을 정하고 실제 시험·운영 기록으로 답해야 한다. 자가평가 작성, 도구 사용, 법적 의무 충족은 각각 구분한다.

## 3. ALTAI의 7가지 요구사항

아래 질문은 원문 질문의 취지를 요약한 것이며 공식 질문의 직역은 아니다.

| 요구사항 | 평가 질문 예시 | 증거 예시 |
| --- | --- | --- |
| 인간의 주체성과 감독 | 사용자가 AI의 역할을 이해하고, 담당자가 결과를 검토·중단할 수 있는가 | 사용자 안내, 검토 권한, 중단 절차 |
| 기술적 견고성과 안전성 | 오류·공격·환경 변화와 낮은 신뢰도의 결과에 대응하는가 | 장애·공격 테스트, 대체 절차, 사고 기록 |
| 개인정보 보호와 데이터 거버넌스 | 필요한 데이터만 수집하고 접근·보관·삭제를 관리하는가 | 데이터 목록, 접근권한, 보관·삭제 정책 |
| 투명성 | 사용한 데이터·모델·규칙을 추적하고 설명의 이해도를 확인하는가 | 버전 기록, 출처, 사용자 이해도 평가 |
| 다양성·비차별·공정성 | 영향을 받는 집단과 편향 지표를 정하고 접근성을 평가하는가 | 집단별 평가, 지표 선택 이유, 접근성 점검 |
| 사회·환경적 안녕 | 사회적 영향과 AI 운영의 자원 사용을 평가하는가 | 영향 분석, 자원 사용·개선 기록 |
| 책임성 | 감사·문제 신고·구제 절차와 원칙 간 충돌의 판단 근거가 있는가 | 책임자, 검토 기록, 신고·정정 이력 |

ALTAI는 개선점을 찾는 자기평가 도구다. 원문도 자기평가 결과가 일곱 요구사항의 충족을 보장하지 않는다고 설명한다.

## 4. 개발·위험관리·법적 요구·시험으로 연결하기

### 4.1 TTA: 개발 과정에 적용

사용자가 공유한 자료는 **2024 신뢰할 수 있는 인공지능 개발 안내서 – 일반 분야**다. 안내서의 활용 흐름은 위험 영향 분석, 서비스에 맞는 요구사항 선정, 증거에 기반한 자가 점검으로 이어진다.

| 영역 | 핵심 점검 내용 |
| --- | --- |
| 생애주기 관리 | 위험 식별·평가·대응, 책임 분담, 테스트, 로그·변경 이력 |
| 데이터 수집·처리 | 출처·구축 시점·버전, 이상값·공격, 수집·라벨링·표본 편향 |
| 모델 개발 | 의존 구성요소 관리, 편향·공격 평가, 모델 명세와 설명 |
| 시스템 구현 | 코드·화면의 편향, 안전모드, 사람 개입, 사용자가 이해할 수 있는 설명 |
| 운영 | 서비스의 목적·범위·한계와 AI·사람의 역할 안내 |

적용하지 않는 항목도 이유를 남긴다. 데이터나 운영 환경이 바뀌면 요구사항과 시험을 다시 검토한다.

출처: [공유 폴더의 일반 분야 PDF](https://drive.google.com/file/d/1ez3CO1sAPIkhc40qayIpE4ziX422ldd2/view), [TTA 공식 웹판](https://tta-trustworthy-ai.gitbook.io/general), [활용 방법](https://tta-trustworthy-ai.gitbook.io/general/p1/5.).

### 4.2 NIST AI RMF: 지속적인 위험관리

| 기능 | 수행할 일 |
| --- | --- |
| GOVERN | 정책, 역할·책임, 위험 허용 기준과 검토 체계 설정 |
| MAP | 사용 목적, 환경, 영향을 받는 사람과 잠재적 위험 파악 |
| MEASURE | 정량·정성 평가, 운영 중 성능과 위험 측정 |
| MANAGE | 위험 우선순위 결정, 완화, 모니터링, 사고 대응 |

네 기능은 한 번 수행하고 끝내는 순차 단계가 아니다. GOVERN은 전체 과정에 걸쳐 작동한다.

AI RMF 1.0의 주요 신뢰성 특성은 타당성·신뢰성, 안전성, 보안·회복탄력성, 책임성·투명성, 설명가능성·해석가능성, 개인정보 보호 강화, 유해 편향을 관리하는 공정성이다. 항목 사이의 상충관계는 사용 맥락에 따라 판단하고 기록한다.

처음 공유된 [NIST 일반 RMF 링크](https://csrc.nist.gov/projects/risk-management/about-rmf)는 보안·개인정보 위험관리 자료다. AI 관련 학습에는 [AI RMF 공식 페이지](https://www.nist.gov/itl/ai-risk-management-framework), [Core](https://airc.nist.gov/airmf-resources/airmf/5-sec-core/), [신뢰성 특성](https://airc.nist.gov/airmf-resources/airmf/3-sec-characteristics/)을 사용한다.

### 4.3 EU AI Act: 적용 대상과 의무 구분

학습의 출발점은 Article 6과 Annex III의 적용 조건이다. 특정 제품·안전 구성요소에 관한 조건과 Annex III에 열거된 사용 목적 등을 확인해야 하며, 서비스가 중요하다는 이유만으로 고위험으로 분류하지 않는다.

다음은 고위험 AI 관련 Articles 9–15의 학습용 핵심 구조다.

| 조항 | 핵심 요구사항 |
| --- | --- |
| [Article 9](https://ai-act-service-desk.ec.europa.eu/en/ai-act/article-9) | 생애주기에 걸친 위험관리 |
| [Article 10](https://ai-act-service-desk.ec.europa.eu/en/ai-act/article-10) | 데이터와 데이터 거버넌스 |
| [Article 11](https://ai-act-service-desk.ec.europa.eu/en/ai-act/article-11) | 기술문서 작성·관리 |
| [Article 12](https://ai-act-service-desk.ec.europa.eu/en/ai-act/article-12) | 기록·로그 기능 |
| [Article 13](https://ai-act-service-desk.ec.europa.eu/en/ai-act/article-13) | 운영자를 위한 투명성과 정보 제공 |
| [Article 14](https://ai-act-service-desk.ec.europa.eu/en/ai-act/article-14) | 인간의 감독 |
| [Article 15](https://ai-act-service-desk.ec.europa.eu/en/ai-act/article-15) | 정확성·견고성·사이버보안 |

이 표는 전체 준수 의무를 열거한 것이 아니다. FitHome의 적용성은 실제 제공 국가, 용도, 고객·운영자 역할과 최신 법령에 따라 별도 검토한다. 이 문서는 FitHome의 고위험 해당 여부를 판정하지 않는다.

학습 시 일부 공식 조문 안내에 개정 반영 관련 주의가 있어 적용 일정이나 세부 예외를 이 문서에 확정하지 않았다. 실제 사업화 시 최신 법문과 공식 안내를 다시 확인한다.

출처: [Article 6](https://ai-act-service-desk.ec.europa.eu/en/ai-act/article-6), [Annex III](https://ai-act-service-desk.ec.europa.eu/en/ai-act/annex-3), [EU 공식 AI Act 안내](https://digital-strategy.ec.europa.eu/en/policies/regulatory-framework-ai), [사용자가 공유한 Chapter III 해설](https://artificialintelligenceact.eu/chapter/3/).

### 4.4 CDAO: 역할과 우려사항을 운영 기록으로 연결

2023년 공개된 RAI Toolkit은 책임 있는 AI 원칙을 프로젝트 생애주기의 평가·도구·산출물에 연결한다. 학습 시 공개 링크는 현재 AIA Toolkit 안내로 이어졌다.

활용할 내용은 다음과 같다.

- SHIELD 평가 흐름에 따라 기반 설정, 실행 구체화, 개선, 상태 평가, 기록, 모니터링을 연결한다.
- 우려사항을 구체적인 문장으로 기록하고 담당자·완화 조치·확인 결과를 붙인다.
- RASCI 방식으로 실행자, 최종 책임자, 지원자, 자문 대상, 공유 대상을 구분한다.
- 도구 목록에 포함되었다는 사실을 정부의 승인·보증으로 해석하지 않는다.

출처: [2023 공개 보도자료](https://www.war.gov/News/Releases/Release/Article/3588743/cdao-releases-responsible-ai-rai-toolkit-for-ensuring-alignment-with-rai-best-p/), [AIA Toolkit 안내](https://www.tradewindai.com/aia-toolkit), [Executive Summary](https://rai.acqbot.com/executive-summary), [Tools List](https://rai.acqbot.com/tools-list).

### 4.5 AI Verify: 시험 결과와 절차의 증거 확보

AI Verify 프레임워크는 원칙을 달성 결과, 실행 절차, 문서 증거로 연결한다. 전통적인 머신러닝의 기술 시험과 조직의 절차 점검을 함께 다룬다.

- **AI Verify Toolkit:** 모델의 공정성·견고성 등 기술 시험과 절차 점검에 활용한다.
- **Project Moonshot:** LLM·LLM 애플리케이션의 벤치마크, 레드팀 시험, 사용자 정의 평가에 활용할 수 있다.
- 프레임워크의 생성형 AI 고려사항과 개별 도구가 실제 지원하는 모델·시험 범위를 구분한다.
- 시험 결과는 특정 조건에서 확보한 증거다. 도구 사용만으로 모든 위험·편향이 제거되거나 안전 인증을 받았다고 표현하지 않는다.

출처: [AI Verify 프레임워크](https://aiverifyfoundation.sg/what-is-ai-verify/), [Toolkit](https://aiverifyfoundation.sg/what-is-ai-verify/toolkit/), [Moonshot](https://aiverifyfoundation.sg/project-moonshot/), [공식 저장소](https://github.com/aiverify-foundation/aiverify).

| TAI-02 | 가격·비율·점수 설명이 원천 데이터와 계산 결과에 일치하도록 검증한다 | 정답 계산 사례, 단위 변환·반올림 규칙, 불일치 기록 |
| TAI-03 | 확인하지 못한 권리관계나 부족한 데이터로 주택의 안전을 단정하지 않는다 | 정보 누락·오래된 데이터·도구 실패 시나리오와 응답 기록 |
| TAI-04 | 가구 유형·지역·언어별 추천 품질과 데이터 커버리지 차이를 평가한다 | 집단별 표본 수·오류·누락률, 차이의 원인과 개선 기록 |
| TAI-05 | 주소·직장 위치·계약 문서의 수집·전송·보관·삭제 범위를 관리한다 | 데이터 흐름, 외부 AI 전송 항목, 접근권한·보관·삭제 확인 |
| TAI-06 | 외부 데이터·문서의 지시가 시스템 규칙이나 접근권한을 바꾸지 못하도록 보호한다 | 프롬프트 인젝션·민감정보 요청·도구 오용 시나리오 |
| TAI-07 | 정보 부족·장애·분쟁에 대한 답변 보류, 담당자 검토, 수정·중단 절차를 마련한다 | 대응 절차와 역할, 운영 훈련, 신고·정정 이력 |
| TAI-08 | 결과 생성에 사용한 데이터·모델·프롬프트·계산식 버전을 추적한다 | 필요한 범위의 마스킹된 로그, 버전·변경·재현 기록 |
| TAI-09 | 언어·통화·면적·주소·계약 관행의 차이를 국가별로 검증한다 | 현지 사례, 번역 검토, 변환 시험, 현지 사용자 평가 |
| TAI-10 | 주거정보 접근성과 운영 자원 사용을 평가하고 개선한다 | 접근성·사용성 결과, 호출량·컴퓨팅 사용량·최적화 기록 |

사용자 조건에 따른 개인화와 부당한 차별은 구분한다. 모든 집단에 동일한 추천 결과를 주는 것을 공정성의 유일한 목표로 설정하지 않는다.

정확한 계산도 입력 데이터의 오류나 권리관계 누락을 해결하지는 않는다. 수치 일치 검증과 데이터 적합성·최신성·충분성 검증을 함께 수행한다.

## 6. 평가 지표와 시험 설계

지표는 목표치를 임의로 확정하지 않고 서비스의 위험과 사용 목적에 맞춰 정한다. 아래 지표의 분모·제외 조건·평가자·데이터셋 버전을 먼저 고정한다.

| 지표 | 측정 방식 |
| --- | --- |
| 수치 일치율 | 참조 데이터·계산 결과와 일치한 수치 주장 수 / 검증 가능한 전체 수치 주장 수 |
| 근거 누락률 | 필요한 근거가 누락된 사실 주장 수 / 근거가 필요한 전체 사실 주장 수 |
| 근거 적합률 | 연결된 근거가 해당 주장을 실제로 뒷받침하는 사실 주장 수 / 근거가 연결된 전체 평가 대상 사실 주장 수 |
| 근거 없는 안전 단정률 | 확인 부족 상황에서 안전을 단정한 응답 수 / 해당 상황의 전체 평가 응답 수 |
| 적절한 보류·전환율 | 사전에 보류·사람 검토가 필요하다고 정한 사례 중 올바르게 대응한 사례 비율 |
| 집단별 품질 | 국가·언어·지역·가구 유형별 오류·누락·추천 품질을 표본 수와 함께 비교 |
| 설명 이해도 | 사용자가 추천 이유와 미확인 항목을 정확히 이해했는지 과제로 평가 |
| 장애 대응 성공률 | 장애 시나리오별 사전에 정한 대체 동작·알림·보류의 성공 비율 |
| 개인정보 보호 시험 | 시험 조건에서 민감정보 노출·권한 위반·보관 또는 삭제 실패가 발생했는지 기록 |

수치 일치율과 함께 전체 수치 주장 수, 검증 가능한 수치 주장 수, 검증 범위 비율을 보고한다. 각 비율의 분모가 0이면 해당 지표는 N/A로 표시한다.

참조 데이터 자체가 없거나 오류가 있는 사례는 수치 일치율 계산에서 무리하게 정답으로 처리하지 않고 별도의 미검증·데이터 오류 건수로 보고한다. 정상 사례의 불필요한 답변 보류율도 함께 측정해 유용성이 떨어지지 않는지 확인한다.

기본 시험에는 정상 조회, 데이터 누락·지연, 동명 단지 오매칭, 통화·면적 변환, API 중단, 유도 질문, 외부 문서의 악성 지시, 민감정보 요청, 다국어·가구 조건 변경을 포함한다. 외부에 내보내는 평가 자료는 합성·비식별 사례를 우선 사용한다.

각 시험에는 다음 정보를 남긴다.

- 사례 ID, 대상 위험과 기대 동작
- 데이터셋·모델·프롬프트·도구·계산식 버전
- 관측 결과, 통과 여부, 판정 근거와 평가자
- 실패 원인, 수정 내용, 재시험 결과
- 잔여 위험, 검토 책임자와 다음 확인 시점

이번 문서 작성에서는 평가 도구를 실행하거나 위 지표의 실측값을 산출하지 않았다. 실제 평가가 끝난 항목만 측정값과 증거 링크를 채운다.

## 7. 해외 확장과 사업화에 연결

해외 확장은 국가별 데이터 접근성, 이용 조건, 사용자 요구와 제도를 확인하며 진행한다. 사업 방향은 기업 구독, API 사용량 과금, 기업·대학 공급, 현지 파트너 브랜드 서비스 구축·운영 등 여러 수익모델을 검증하는 것이다. 가격과 계약·매출은 검증 전 사업 가정으로 구분한다.

| 기간 | 사업·제품 계획 | 신뢰성 AI 검증 과제 |
| --- | --- | --- |
| 1–3개월 | 국내 사용성 검증, 해외 수요·경쟁·데이터 조사, 첫 진출국 선정 | 위험·책임 정의, 출처·커버리지 파악, 초기 평가 사례 작성 |
| 4–6개월 | 유료 상품 검증, 현지 데이터 연결, 다국어 기능 개발 | 수치·단위·언어 검증, 데이터 이용 조건과 외부 전송 경로 검토 |
| 7–12개월 | 현지 파트너 발굴, 시범 운영, 리포트 현지화 | 현지 사용자 이해도, 집단별 품질, 장애·사람 개입 절차 평가 |
| 13–24개월 | 해외 유료 계약·API 공급 확대, 후속 국가 진출 검토 | 변경 시 재평가, 사고·정정 추적, 현지 운영·규정 변화 점검 |

파트너에게 제공할 자료는 서비스 범위·한계, 데이터 명세, 평가 조건과 결과, 사람의 검토 절차, 변경·오류 대응 기록이다. 이러한 자료는 각 파트너의 검토에 활용할 근거이며 법적 적합성이나 안전성을 일괄 보증하는 문서로 사용하지 않는다.

| 자료 | 이번 학습 범위 |

모든 원문을 전부 정독하거나 모든 도구를 설치·시험한 결과는 아니다. TTA PDF와 지속 개정되는 웹판의 항목 수·버전을 혼용하지 않는다. CDAO의 개별 도구 목록 전체는 확인하지 않았다.

원칙·평가 기준·법령·도구가 개정되거나 FitHome의 데이터, 고객, 제공 국가, 모델이 바뀌면 이 문서를 다시 검토한다. 갱신 시 변경 이유, 확인한 출처·판본·날짜, 추가 시험 필요 여부를 함께 기록한다.
